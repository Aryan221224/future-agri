# Training the perception model on the Bennett H200 server

One job: fine-tune **RF-DETR-Medium** on **WeedsGalore** (CC BY 4.0, 156 UAV patches, maize and
four weed classes), calibrate the conformal gate on real detections, export to ONNX. Results go
to `ml/results/wg-medium/`. Nothing here needs sudo; everything stays under `/home/paawan_kumar`.

Why this dataset: it is real drone imagery with instance labels, its licence allows shipping the
model (ADR 0009), and the pipeline in this folder already converts it.

## What you need on the laptop

- PuTTY session `NVIDIA-GPU` and WinSCP session `NVIDIA-GPU` (already saved)
- `futureagri_h200.tgz` (this repo, about 300 KB)
- Optional: `weedsgalore-dataset.zip` (321 MB), downloaded in a browser from
  https://doidata.gfz.de/weedsgalore_e_celikkan_2024/ — only needed if `preflight.sh` shows the
  dataset host as blocked

## Steps

1. **WinSCP**: upload `futureagri_h200.tgz` to `/home/paawan_kumar/`.
   If you have the dataset zip, create `/home/paawan_kumar/data/downloads/` and upload
   `weedsgalore-dataset.zip` there.
2. **PuTTY** (log in with your own password; never put it in a file):
   1. `cd /home/paawan_kumar`
   2. `tar xzf futureagri_h200.tgz`
   3. `cd futureagri`
   4. `bash ml/h200/preflight.sh` — shows free GPUs, free disk, Docker, and which download hosts
      the server can reach. Send me the output.
   5. `bash ml/h200/launch.sh` — picks an idle GPU, starts the job detached, prints the log path.
   6. `tail -f /home/paawan_kumar/futureagri/ml/runs/wg-medium/pipeline_log.txt` (Ctrl-C leaves
      the job running). You can close PuTTY and the laptop.
3. When the log ends with `DONE`, download `ml/results/wg-medium/` with WinSCP into
   `C:\Users\aryan\Documents\FutureAgri\futureagri\ml\results\wg-medium\`.
   Also download the whole log `ml/runs/wg-medium/pipeline_log.txt`.
4. Free the GPU: the container removes itself when the job ends. Check with `docker ps`.
   Delete what you don't need (`ml/runs/wg-medium/*.pth` after you have downloaded the best one).

Optional second run, larger model, only after the first finishes: `bash ml/h200/launch.sh large 100`.

## If something fails

| Symptom in the log | What to do |
|---|---|
| `No idle GPU` | Wait, or `GPU=<n> bash ml/h200/launch.sh` for a GPU you saw idle in `nvidia-smi` |
| pip cannot reach PyPI / huggingface / GCS | Host is blocked. Tell me which; the weights or wheels have to be downloaded on the laptop and uploaded with WinSCP |
| dataset download failed | Upload `weedsgalore-dataset.zip` as in step 1 and run `launch.sh` again (it skips finished steps) |
| `rfdetr` install fails on `torch-hungarian` or `onnx*` | The script retries without ONNX and skips export. Send the log |
| CUDA out of memory | Another user took the GPU. Re-launch on a different one |
| container exits immediately | `docker logs fa-wg-medium` is empty because of `--rm`; read `ml/runs/wg-medium/pipeline_log.txt` |

## Rules of the server

- Work only under `/home/paawan_kumar`. Release the GPU when finished. Keep your own copy of the
  results: the account lasts one week from creation (about 5–6 Nov), and an extension has to be
  requested from the NVIDIA System Team.
- Disk is tight: the run keeps only the best checkpoints and deletes the rest.
- Not tested on the H200 itself (it was written without access to it). The first `launch.sh` is
  the test; the log tells what to fix.
